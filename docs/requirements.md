## 一、 三级人员权限体系与全院业务流转关系

### 1.1 三大核心角色定义
1. **系统管理员（信息科人员 `sys_admin` —— 全院最高权限）**
   - **管理范围**：全院科室架构配置（划分主库房管理科室与临床二级库科室）、全院人员账号注册审批与添加、**全流程业务链路日志增删改查与合规监管**、系统全局参数与 5 大智能体运行监控。
2. **科室管理员（各职能管理科室权限 `dept_manager`：耗材科、设备科、财务科）**
   - **耗材科管理员 (`CONSUMABLE_DEPT`) / 设备科管理员 (`EQUIP_DEPT`)**：
     - 维护【产品字典】（设置产品归口主科室、划分耗材分类）；
     - 负责【普通耗材管理（主库全部物资总仓）】的采购验收入库、库内盘点，并根据需求或申领单**按需分发给临床二级库或转入高值耗材仓库**；
     - 负责【高值耗材管理（高值专仓）】的一物一码赋码、效期管控与手术跟台审核；
     - 审批临床二级库提交的申领单与退库单，执行《主库入库单》与《主库按需分发调拨单》打印。
   - **财务科管理员 (`FINANCE_DEPT`)**：
     - 负责全院主库入库、按需分发、二级库消耗与高值核销的台账核对；
     - 执行全院多维度**统计查询**、临床科室月度耗材成本核算审核，打印《财务科月度科室耗材结算单》。
3. **科室人员（临床二级库人员 `secondary_user`：如骨科、心内科、手术室、检验科等）**
   - **管理范围**：所属临床科室【二级库管理】；
   - **核心动作**：向归口主库（耗材科/设备科）发起物资申领单；扫码签收主库按需分发过来的物资入二级库（或发现破损差异执行拒收）；登记本科室日常普通耗材消耗扣减；登记高值耗材绑定患者住院号扫码核销；发起向主库的逆向退库；打印《临床二级库申领/领用单》。

### 1.2 各个用户之间的标准业务流转链路
```text
[信息科管理员] 维护科室架构(耗材科/设备科/财务科/各临床二级库)与用户角色，全程监控【全流程业务链路日志】
      |
      v
[耗材科 / 设备科管理员]
  1. 在【产品字典】建档产品，绑定“主库房下的主科室(耗材科/设备科)”与“耗材分类(普通耗材/高值耗材/设备配件)”
  2. 全部外购物资统一在【普通耗材管理(主库总仓)】完成批次验收入库，打印《主库入库单》
  3. 执行【按需分发】：创建分发调拨单，打印《主库按需分发调拨单》，分两条路径下发：
      +----------------------------------------+----------------------------------------+
      | 分发路径 A：转入【高值耗材仓库】         | 分发路径 B：分发至【临床科室二级库】       |
      v                                        v                                        |
[高值耗材管理(一物一码专仓)]              [临床科室人员(二级库管理)]                     |
  - 触发“由量到码”拆包，生成独立 UDI 唯一序列号    - 在线向主库发起申领(按归口主科室自动路由)    |
  - 分拨至手术室/临床二级库专柜                  - 签收主库分发物资，自动增加二级库库存        |
  - 临床人员绑定患者住院号扫码使用核销            - 科室日常领用消耗扣减 / 临期物资逆向退回主库  |
      +----------------------------------------+----------------------------------------+
                                               |
                                               v
                                    [财务科管理员]
                                      - 遵循“移库不计费、消耗即结算”原则核算各科室真实耗材成本
                                      - 多维【统计查询】、月度结算审核、打印《财务结算汇总单》
```

## 二、 产品经理（PM）六大深度业务规则（核心业务逻辑基石）

1. **规则一：主科室归口专管与申领自动分流规则**
   - 【产品字典】中每件产品唯一指定`主库房归口主科室`（耗材科主库 / 设备科主库）。
   - 临床二级库发起申领时，系统按产品归口主科室定向路由至对应主科室管理员审批与分发，做到“谁主管、谁审批、谁发料”。
2. **规则二：主库全部物资统管与“由量到码”分拨转换规则**
   - 全部物资入主库总仓时按“产品 + 生产批号 + 数量”管理；
   - 当按需分发至【临床二级库】时，按批次数量直接调拨；当按需分发至【高值耗材仓库】时，触发**“批次拆包赋码（一物一码激活）”**，按件生成独立的 UDI 唯一序列号单品记录，实现全周期单品级追踪。
3. **规则三：“三流合一”两阶段财务记账规则**
   - **移库不计费**：主库向二级库或高值仓按需分发属于院内库房位置转移，不计入临床科室成本；
   - **消耗即结算**：仅当二级库登记“日常领用消耗”或高值耗材完成“绑定患者扫码核销”时，才正式生成财务结算流水并计入对应临床科室成本。
4. **规则四：逆向业务回路与效期硬风控规则**
   - **效期硬拦截与 FEFO**：批次过期自动置为 `EXPIRED（过期冻结）`，严禁分发与临床核销；主库分发默认按 **FEFO（近效期先出）** 排序推荐批次；
   - **逆向闭环**：完整支持二级库签收差异拒收（库存回滚主库）、二级库向主库逆向退库、以及过期/破损物资报损核销。
5. **规则五：全流程业务链路日志“6W 物权责任交接契约”**
   - 每条业务流转日志强制记录 6 大法定要素：①物资与批次/UDI码（What）、②8大标准业务节点动作（Which Action）、③交出科室与交出用户（From）、④接收科室与接收用户（To）、⑤变动数量与变动前后库存快照（How Much）、⑥关联业务单号与审计状态（Audit Status）。
6. **规则六：医院标准 5 类法定单据打印规范**
   - 支持打印《主库验收入库单》、《主库按需分发调拨单》、《高值耗材一物一码核销单》、《临床二级库物资申领/退库单》、《财务科月度科室耗材结算单》，票面强制包含单据条码、状态水印、批次效期明细及票尾**【制单人 / 主库科室管理员 / 二级库接收人 / 财务科复核】四联签字栏**。

## 三、 传统业务模块：5 套核心 CRUD + 统计查询 + 单据打印明细

1. **基础支撑模块**：登录、注册与用户科室管理 CRUD（`sys_user`、`sys_department`）
2. **核心 CRUD 一：产品字典管理**（`spd_category`、`spd_product_dict`）—— 维护主库房下主科室归属、耗材多级分类、产品标准信息与安全库存阈值。
3. **核心 CRUD 二：普通耗材管理（主库全部物资管理 + 按需分发）**（`spd_main_inventory`、`spd_distribution_order`）—— 全部物资验收入主库、批次效期管理、**按需分发给临床二级库或转入高值耗材仓库**。
4. **核心 CRUD 三：高值耗材管理（一物一码专仓）**（`spd_high_value_item`）—— 高值耗材 UDI 唯一序列号建档、跟台备货、绑定患者住院号扫码核销、异常批次召回冻结。
5. **核心 CRUD 四：二级库管理（临床科室库房）**（`spd_secondary_inventory`、`spd_requisition_order`）—— 二级库向主库申领、签收主库分发物资、临床日常消耗扣减、逆向退库与二级库盘点。
6. **核心 CRUD 五：全流程业务链路日志管理**（`spd_workflow_log`）—— 对跨科室、跨用户的 8 大流转节点日志执行完整的增（自动埋点+人工补录）、删（信息科清理归档）、改（异常审计标注与复核备注）、查（按单号/用户/科室/UDI 时间轴穿透查询）。
7. **支撑中心：统计查询与单据打印** —— 多维库存/消耗/耗占比统计报表与 5 类标准医疗单据打印。

## 四、 5 大业务智能体流程与各节点作用详解（录制视频讲解核心蓝图）

### 4.1 智能体 1：产品字典智能归类与主库入库合规审查智能体
- **服务角色**：耗材科管理员、设备科管理员
- **节点流程图与作用**：
  1. `[input_parse_node (入库与字典参数提取节点)]`：提取待建档或待入库产品的名称、规格、UDI 条码、注册证号与实测温度。
  2. `[rag_catalog_retrieve_node (Chroma 法规与分类目录检索节点)]`：检索《医疗器械分类目录》与主库验收 SOP。
  3. `[mcp_db_cert_check_node (MCP 业务库字典与资质核查节点)]`：查询 MySQL `spd_product_dict` 表，校验注册证效期与批次剩余效期。
  4. `[compliance_router_node (条件路由判定节点)]`：判定产品归属主科室（耗材科/设备科）、区分普通/高值耗材，并检验是否触发过期/超温硬拦截。
  5. `[report_output_node (审查结论与货位推荐生成节点)]`：输出分类建档建议、推荐主库货位或生成违规拒收拦截单。

### 4.2 智能体 2：主库全部物资智能按需分发与补货调拨智能体
- **服务角色**：耗材科管理员、设备科管理员
- **节点流程图与作用**：
  1. `[mcp_scan_inventory_node (主库与二级库水位扫描节点)]`：调用 MCP 扫描 `spd_main_inventory`（主库总仓）与 `spd_secondary_inventory`（各临床二级库缺口）。
  2. `[fefo_batch_calc_node (FEFO 近效期批次匹配精算节点)]`：按“近效期先出”原则锁定主库最优批次，区分发往【临床二级库】或【高值耗材仓】。
  3. `[rag_dispatch_rule_node (Chroma 院内调拨规范检索节点)]`：检索医院二级库定数包补货与高值转仓管理规定。
  4. `[mcp_write_dispatch_node (MCP 自动生成按需分发单节点)]`：直接向 MySQL `spd_distribution_order` 表写入分发草稿单并同步写入全流程日志。

### 4.3 智能体 3：临床二级库自然语言申领与耗材规范问答智能体
- **服务角色**：临床各科室（二级库）人员
- **节点流程图与作用**：
  1. `[nl_intent_extract_node (自然语言意图与手术实体解析节点)]`：识别临床人员是“日常问答”还是“发起手术/科室耗材申领”。
  2. `[rag_surgery_manual_node (Chroma 手术配包与说明书检索节点)]`：从向量库匹配对应手术的标准耗材配包清单或产品使用注意事项。
  3. `[mcp_check_stock_node (MCP 主库可用余量核验节点)]`：查询 MySQL 确认耗材科/设备科主库是否有足够库存。
  4. `[mcp_create_requisition_node (MCP 自动创建二级库申领单节点)]`：按归口主科室自动生成 `spd_requisition_order` 申领单并写入流转日志。

### 4.4 智能体 4：高值耗材一物一码与跨用户流转日志全链路溯源智能体（支持原生 LangGraph / Coze）
- **服务角色**：信息科系统管理员、耗材科/设备科管理员
- **节点流程图与作用**：
  1. `[udi_input_node (异常 UDI 序列号/批号接收节点)]`：接收待追查的高值耗材 UDI 唯一码、生产批号或业务单号。
  2. `[mcp_full_trace_node (MCP 跨表穿透查询人物流转链节点)]`：联查 `spd_high_value_item` 与 `spd_workflow_log`，完整还原“主库入库人 -> 按需分发人 -> 高值仓/二级库签收人 -> 临床患者核销人”全链路轨迹。
  3. `[mcp_auto_freeze_node (MCP 在库风险批次一键冻结节点)]`：自动将主库、高值仓、二级库内同批次未使用的耗材状态更新为 `RECALLED（召回冻结）`。
  4. `[rag_recall_sop_node (Chroma 不良事件法规检索与报告生成节点)]`：检索《医疗器械召回管理办法》，输出流转关系图谱与应急召回报告（支持同步桥接 Coze 智能体 Webhook）。

### 4.5 智能体 5：多科室耗材统计精算与财务流转合规审计智能体
- **服务角色**：财务科管理员、信息科系统管理员
- **节点流程图与作用**：
  1. `[mcp_finance_agg_node (MCP 多科室消耗金额与日志聚合节点)]`：按两阶段财务记账法则，汇总各二级库普通耗材与高值耗材实际消耗金额。
  2. `[anomaly_detect_node (跨用户异常流转与超标消耗识别节点)]`：扫描 `spd_workflow_log` 中超时未签收、频繁退库或耗占比异常突增的科室。
  3. `[rag_audit_policy_node (Chroma 财务内控与耗占比制度检索节点)]`：检索医院财务耗占比考核标准与内控审计红线。
  4. `[audit_report_gen_node (财务核算与合规审计报告生成节点)]`：生成月度各科室成本核算表、异常流转预警清单与整改建议。

## 一、系统级深层问题自我诊断与排查清单

### 1. 致命鉴权漏洞：离线伪降级导致“输错密码也能登录”
- **代码根因**：`frontend/src/stores/userStore.ts` 第 248-265 行。
  - 在 `login(account, password)` 中，调用后端 `/auth/login` 失败时（后端正常返回 400 提示密码错误），前端将其放入 `catch` 块；
  - 随后在 `if (!backendSuccess)` 逻辑中，直接将用户输入的工号或默认 `PRESET_USERS[0]` 赋值给 `this.currentUser`，并签发伪造 Token `spd_token_${matched.username}_${Date.now()}`，强行令 `this.isLoggedIn = true`！
  - **业务后果**：用户随意输入错误密码甚至乱码账号都能直接登入系统，鉴权形同虚设！
- **整改规范**：
  - 彻底移除错误兜底放行逻辑；后端返回 400 时，坚决抛出异常并提示“工号或访问密码不正确，请核对后重试”；
  - 演示免密通道仅在用户明确点击【演示角色一键免密体验】网格按钮时，通过专用的安全通道建立受控演示会话。

### 2. 路由导航越权漏洞：前端缺少角色级别路由拦截
- **代码根因**：`frontend/src/router/index.ts` 导航守卫中仅判断了 `!userStore.isLoggedIn`。
- **业务后果**：二级库护士或外部供应商在浏览器地址栏手动输入 `/users`（全院人员与RBAC中心）或 `/procurement`，路由守卫直接放行，存在重大越权风险。
- **整改规范**：
  - 在路由元信息 `meta.roles` 中严格配置准入角色列表（如 `/users` 仅限 `sys_admin`，`/secondary` 仅限 `secondary_user` 与 `sys_admin`）；
  - 全局前置守卫中比对当前登录人员的 `roleCode`，无权限时重定向至无权限友好提示页或其所属工作台，并提示“您当前岗位角色暂无权限访问该业务工作台”。

### 3. UI 视觉与表单填写的工程统一性缺失
- **现状缺陷**：
  - 表单控件混杂：部分页面手写原生 `<input class="spd-input">`，部分页面使用 `<el-input>`，边框颜色、内边距、圆角与高度参差不齐；
  - 布局混乱：弹窗表单有的为单列居中，有的为双列网格，缺少统一的栅格间距；
  - 必填标识不一致：有些必填字段带红色星号，有些不带；
  - 字体不规范：单据号、批号、金额、数量混用系统默认无衬线字体，未应用等宽数字字体 `font-mono tabular-nums`，导致表格上下行数字对不齐；
  - 按钮层级与交互缺失：高频点击无防抖或 Loading 锁，危险操作（如驳回、拒收、作废）缺乏二次警示。
- **整改规范**：
  - **统一表单组件规范**：所有弹窗与页面表单采用标准 2 列或 4 列自适应网格（`grid-template-columns: repeat(2, 1fr)`，`gap: 16px`）；
  - **标签与控件统一**：标签固定置于输入框上方（`font-size: 12px; font-weight: 600; color: var(--text-primary)`），必填字段前置统一红色星号；
  - **控件尺寸标准化**：统一高度为 `38px`（紧凑医疗专业版）或 `42px`，边框 `1.5px solid var(--border-card)`，圆角 `8px`，聚焦时光圈自适应当前主题；
  - **业务数值等宽对齐**：所有单据号（`TR...` / `CK...` / `DIST...`）、物料编码、UDI 码、批次号、单价、数量强制挂载 `font-mono tabular-nums`；
  - **操作栏标准化**：弹窗底部右对齐固定为【取消】（次级平级按钮）与【提交/确认】（主品牌高亮按钮），提交时强制开启微加载 Spinner 并锁定按钮防重复提交。

### 4. 账号与账号间业务流转与双向审核链路断层
- **链路 1：普通耗材临床请领 -> 主库受理 -> 二级库接收**
  - 二级库护士提报 -> 主库管理员审批通过（**必须原子扣减主库库存**） -> 自动派发二级库待接收分发单 -> 二级库护士实物核验并确认入库（**二级库增库计入资产**）；
  - 主库管理员驳回必须填写驳回原因，二级库端可见退回状态与原因说明。
- **链路 2：跨病区科室调拨双向审核**
  - 调出科室开单：单号系统全自动生成（`TR936...` 只读不可改），调出科室系统锁定，调入科室动态下拉选择系统中已有二级库；
  - 调出科室提交：调出科室在库库存预占/扣除，单据状态设为 `PENDING_TARGET_RECEIVE`（在途调拨）；
  - 调入科室审核：调入科室进入工作台查看到待审核调入单，核验实物后点击【审核确认入库】（调入科室增库结案）或【驳回拒收】（调出方冲回库存）。
- **链路 3：高值耗材专仓借调与退库双向审核**
  - 急诊跨科室借调：自动生成 `HVT...` 单号，借出专柜冻结单品，借入科室扫码接收确认，使用后核销或原物归还；
  - 临床科室退库：护士发起退库出库单，高值专仓管理员在【退库验收审核】扫码核验无误后恢复入专柜（`IN_HIGH_VALUE_WH`）或转破损。
- **链路 4：供应商准入与采供发货验收双人双签**
  - 供应商注册上传资质证书 -> 医院信息科/耗材科管理员执行资质准入审核通过，未通过供应商禁止下发采购单；
  - 采购订单 -> 供应商在线拣货发货生成待验单 -> 耗材主库双人双签（初验人验收外观批号 + 保管员复核二次确认入库）。

### 5. 管理员最大权限穿透与多院区数据物理隔离契约
- **多院区拓扑**：庆春主院区 (`MAIN_CAMPUS`)、滨江院区 (`BINJIANG_CAMPUS`)、下沙院区 (`XIASHA_CAMPUS`)；
- **普通角色物理隔离**：科室护士与科室管理员仅能查看和操作所属院区及授权科室的物资与单据；
- **管理员全院穿透**：信息科管理员选择“全院全部仓库（穿透模式）”时，可下钻所有院区、主库、二级库、高值专柜的在库批次与金额，并能穿透查看全院所有仓库的期初建账明细。

### 6. 主动排查发现的深层医疗 SPD 业务盲区
1. **扫码枪（条码枪）输入未适配回车自动验码**：
   - 临床实际操作中，护士和库管主要依靠条码枪扫码，条码枪自动在末尾追加 `Enter` 键。现存输入框没有监听 `@keyup.enter`，导致扫码后还需手动点击“查询”或“核验”按钮，极度影响临床效率。
2. **资质到期硬性预警与下单熔断**：
   - 供应商《医疗器械经营许可证》或产品《医疗器械注册证》小于等于 30 天时应黄色预警，已过期时必须硬性阻断下发采购订单和验收出库。
3. **高值扫码核销缺少“撤销核销/冲正”机制**：
   - 临床手术因突发病情变化取消或更换耗材时，已扫码绑定的高值单品必须具备主管护士与库管审批后的“撤销核销冲正”功能，恢复单品在库可用状态。
